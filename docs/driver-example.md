# 教材驱动范例：用真实实验反馈组织自动研究

本例沿用《大模型智能体》章节的组织：**规划、记忆、工具使用和反馈**是核心机制；**上下文工程**组织本轮信息；**驾驭工程**通过运行时循环、权限控制和状态持久化连接模型与环境。

范例中的研究者是大模型，研究对象是强化学习算法；被训练的策略网络不是这个研究者。固定 IQL 为对照，候选源码可修改，价值更新保持 in-sample。没有 RSI，研究者不能修改自身 Harness、预算或评价规则。

## 1. 先看一条主线

```text
读取研究合同和持久状态
→ 装配当前上下文
→ 模型选择一个行动
→ 运行系统校验并执行
→ 获得真实观察，保存结果和反馈
→ 调整计划、取回或写入研究笔记
→ 继续研究，或在证据完整后冻结方法
→ 学生入口执行独立九任务确认
```

真实模型可以按信息缺口选择先查资料、先看实现、先调试或先做局部实验。这是开放的研究路径，不是规定每轮必须先检索若干篇论文的工作流。

正式研究用 `bash start.sh`；它需要教师准备的环境、模型配置和完整预算授权。只读本地机制时可以运行：

```bash
python examples/adaptive_workflow.py --output runs/adaptive-example
```

该示例明确使用脚本控制器与合成环境，真实执行训练、续训和评价，但**不能证明模型因反馈自主选择了这些动作，也不是 D4RL 成绩**。单独查看资料工具链可用 `examples/research_workflow.py --offline-fixture`；测试资料同样不冒充在线论文。

## 2. 目标合同：研究条件固定，研究路径可变

阅读 `core/schema.py` 的 `ResearchContract`，再看 `tasks/iql/study.py` 的 `apply_nine_task_protocol`。这里规定开发池、确认条件、算法权限和预算。`AgentConfig` 保存用户设置的稳定研究指令和上下文上限。

开发池是 HalfCheetah-medium、Hopper-medium-replay、Walker2d-medium-expert，全部 v2。新方向可以先选其中一项、一个 seed、约 5,000 步和 3 个评价 episodes；这不是最终实验要求。模型判断是否值得加码，但不能提前对另六项开发选型。任务和种子等完整数值见[研究协议](nine-task-study.md)。

第一遍先掌握四个对象：**方向组织假设，修订保存代码，轨迹保存训练连续性，端点保存一次观察**。它们分别解决搜索、复现、续训和比较问题，详见[术语表](glossary.md)。

## 3. 规划：从当前证据选择下一项行动

先读 `Harness.run()`，再读 `_decide()` 和 `_execute()`。模型收到当前目标、计划、候选和实验摘要，返回一个有明确参数的行动。`plan` 可以改变后续计划；`propose` 或 `edit_algorithm` 把假设与不可变代码修订连接起来。

当前计划会检查依赖引用与环，但节点 `done` 不直接证明实验完成。真正推进研究的是工具产生的工件和账本。模型可以修改未完成步骤，不必抛弃有效的已有状态。

例如，发现候选数值异常，可以先读堆栈、修复再检查；发现短实验不确定，可以继续同一轨迹、增加开发任务或增加 seed。没有固定“上涨某个分数就晋级”的硬规则。是否值得继续，是模型的研究决策；是否允许执行，由 Harness 检查。

## 4. 上下文：持久事实的有限视图

阅读 `ContextBuilder.build()`。当前输入包含目标、必要约束、活动计划、候选卡片、面板摘要、近期局部观察、可续训端点、少量笔记、来源索引和终止预算。数字由 `PanelIndex` 从账本计算，不由模型重新统计。

完整历史不反复进入模型。需要具体内容时，用 `inspect` 查源码或反馈，`query_experiments` 查实验和缺失项，`read_trial_log` 查堆栈和指标，`read_source` 查正文。裁剪会留下计数和读取入口，不删除原始证据。

这对应章节中的“上下文选择—按需装配—上下文压缩”。本实现没有再调用一个模型压缩数值，也没有自动全局向量记忆；具体视图字段见[上下文说明](context-design.md)。

## 5. 工具：从资料线索到可执行实验

阅读 `core/capabilities.py`、`core/tool_catalog.py` 与 `research/service.py`。

调研先得到来源线索，获取正文后产生 `src-*` 快照，实际读取的范围形成 `span-*`。GitHub 文件固定到具体 commit。研究笔记和假设可以引用这些证据，但搜索结果不等于全文、读过材料不等于证明结论，下载代码也不会自动执行。

`edit_algorithm` 修改候选工作内容，不能修改运行中的 Harness 或正式评分器。候选注册后还须经过明确的 Python 执行授权。学生入口保留免额外搜索密钥的论文和公开仓库工具，通用网页搜索默认关闭；详细工具见[调研说明](research-tools.md)。

`check_candidate` 用极少计算做真实接口检查，记录为 `purpose=check`；它消耗资源，不进入正式排名和完成门禁。`run` 则产生正式开发观察。候选网络、策略形式和价值目标保持开放，不要求所有算法看起来都像 IQL。

## 6. 反馈：检查执行结果，而不是只读一个总分

`TrialService.run()` 的阅读注释按原顺序标出七段：校验范围、建立身份、检查已完成请求、选择恢复点、预留预算、执行训练与评价、提交事实。它没有在本整理版中被拆成新函数。

worker 负责数值更新，独立评价器控制模拟器并计算回报；模型不参与每次梯度更新。候选策略只能按动作接口返回结果，打印“高分”不能成为正式成绩。

失败反馈保留简要堆栈和继续读取入口。代码错误、基础设施错误、约束不满足与有效负结果要分别处理；崩溃不能填成零分。`compare` 只对相同条件做配对，明确指定的局部比较可以指导探索，但不能替代合同要求的完整确认。

value 阶段检查登记的真实状态—动作配对；policy 阶段可以产生新动作并使用冻结 Q。运行钩子只验证可观察接口，不是对任意 Python 的完整正确性证明。详见[算法接口](open-algorithm-api.md)。

## 7. 记忆：保存事实、经验和未解决问题

阅读 `Store` 的实验、事件、工件和记忆接口。实际实验由执行器持久记录，不能由模型笔记改写；`remember` 可以保存观察、假设、修复经验或决策，并引用实验或 source/span。引用存在只证明来源可找回，不证明解释一定成立。

默认上下文优先取回与目标和当前计划有关的少量研究笔记，而不是大量重复的自动实验笔记。被新证据替代的笔记可退出默认使用，原记录仍可追溯。这里主要是当前 Campaign 的跨轮、跨中断状态，不是跨项目自动积累的全局知识库。

合适的记忆会说明：“这个短端点已完成，但长程和其它任务尚未验证。”不应把一次观察直接写成“该方法普遍优于 IQL”。

## 8. 驾驭工程：循环、权限与持久化

**运行时循环。** `Harness.run()` 优先恢复待结算行动，随后再决定是否调用模型；一次工具结束后保存反馈，检查完成、阻塞或预算状态。当前同步等待实验，不是异步集群。

**权限控制。** `enabled_tools()`、`decision_schema()`、`authorize_action()` 使用同一个能力视图。模型可以提议行动，不能因此扩大网络、代码或测试访问权限。部署和最终审计仍是用户操作。

**状态持久化。** 数据库保存待结算行动与事实，训练检查点保存网络、优化器、调度器、额外状态和 RNG。`core/checkpoints.py` 区分轨迹和端点：5,000→20,000 累计端点只增加 15,000 步；日程从首次训练前就固定。增加环境、seed、源码或配置产生新轨迹，增加评价次数则复用训练工件。

失败恢复不等于免费重试，预留的不确定消耗不会自动清零。源码哈希变化会触发原来的完整性保护，即使变化只是注释和排版。

## 9. 冻结与最终确认：能运行不等于结论成立

固定 IQL 与选中方法都满足三个开发任务、确认 seed 0/1/2、百万步、10 个评价 episodes 后，`finish` 才冻结方法。它结束的是开发选择，不是宣告算法提高。

`classroom.session.run_study()` 随后按事先批准的协议调用 `audit_campaign(split="final")`，对九个任务分别重训固定方法与 IQL。不会在全部候选之间挑最终测试最高分，也不把最终分数返给模型继续调优。

`classroom.reporting.study_report()` 检查完整证据并分开全九项、开发三项复验、未用于本次搜索的六项结果。缺任何必需单元就保持待完成。完整面板、统计收益、方法新颖性和 Agent 能力是不同结论。

## 10. 沿工件检查，而不是只看最终段落

默认研究目录为 `.arlab/d4rl9/runs/study/`。`development/` 内有 `contract.json`、`agent.json`、`state.sqlite3`、`frozen.json`、开发报告、`jobs/` 和调研工件；`final/` 保存独立审计及进度；研究目录的 `report.json.research_complete` 才表示完整研究证据状态。

课堂可沿一个候选检查：假设引用哪段材料？哪次工具产生实际结果？为什么续训而不是重训？哪个反馈改变了计划？为什么短程高分仍不能结束？缺少一个 baseline seed 时，哪个门禁拒绝冻结？

以上问题围绕真实输入、行动和状态回答，不需要公开模型隐藏推理。原始教材章节本次未修改；本文件是与该章机制组织对应的仓库讲解。完整源码导航见[阅读指南](reading-guide.md)，验证范围见[整理核对](review-readability.md)。
