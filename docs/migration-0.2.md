# 从 0.1 迁移到 0.2

## 保留了什么

固定 IQL 的默认网络、目标、更新顺序与导出格式保留。
已有 `IQLRecipe` 继续可用。对有符号 Q/V 损失撤掉非负检查不会改变默认平方损失的结果。
`iql-gaussian-mean-v1` 工件仍有独立读取路径，不需要改成 Python policy 才能评价。

原有 Harness、HTTP 模型接口、研究记忆、实验账本、封存评价、H/I 递归谱系继续使用。
增加了源码候选和不可变源码编辑，不是另起一个与原系统不连接的 demo。

## 需要显式调整的地方

新建 campaign 时配置 `code_execution.mode`。这是执行源码的授权，不是 in-sample 的额外数学限制。
已审阅本地运行可选 `trusted_local`；无人值守运行优先配置容器。
旧模式 `disabled` 只运行原有声明式候选。

预算增加 `max_optimizer_steps`，旧合同反序列化有默认值。
一个训练 tick 可以包含不同数量的优化器步骤，请为代码候选设置真实预算并检查输出账本。

0.2 D4RL 导入器在五个原字段外保存 `next_indices`。
旧数据继续支持原始一步 IQL；多步源码模板默认 `n_step=2`，需要重新导入真实链接，
或者显式把该候选配置改为 `n_step=1`。不会凭数组顺序猜测 episode。

## 不原地恢复跨实现实验

旧运行绑定 0.1 的源码与合同哈希；0.2 不应覆盖它们或伪装成同一实验继续。
保留旧目录供追溯，在新目录重新启动合同。已有知识和结果可作为外部经验审阅导入，
不能当成当前源码已经得到的训练结果。

旧版证据移到 `evidence/v0.1-historical/`；本版验证看 `evidence/validation.json`。
模板并非 IDQL 等已发表方法的完整复现，合成环境的小实验也不是 D4RL 成绩。
