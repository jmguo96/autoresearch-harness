# v0.6 上下文：持久事实的有限视图

上下文解决“这一轮看什么”，持久化解决“什么长期保留”。本实现对应教材中的**上下文选择、按需装配和上下文压缩**，不使用第二个模型重写数值，也不增加上下文子智能体。

## 稳定输入与当前状态

模型适配器发送稳定研究指令和当前获准动作 schema；显示用 title/default 被压缩，验证约束保留。`ContextBuilder.build()` 另外装配动态视图，不重复发送全部配方 schema 或候选源码。

| 内容 | 当前默认处理 |
|---|---|
| 目标、必要约束、baseline 身份 | 常驻；细节按合同和工具查回 |
| 当前计划 | 最多六项活动目标及完成计数，完整计划可读 |
| 候选卡片 | 最多十二张；优先 baseline、当前焦点、可冻结方法和活跃分支最新版本 |
| 分支预算 | 活跃方向与累计修订分开计数 |
| 完整训练证据 | `PanelIndex` 按候选与参考端点计算覆盖、缺失、失败、统计和成本 |
| 局部观察 | 最多八项近期完成记录的轻量字段，不代替全任务排名 |
| 可续训记录 | 最多八项可见候选的已完成端点索引 |
| 最近反馈 | 默认约 6,000 字符；完整反馈工件引用保留 |
| 研究笔记 | 默认三条，按研究目标和活动计划检索 |
| 资料来源 | 四个轻量索引；范围和正文由读资料工具取得 |
| 资源 | 实验等预留及硬上限，剩余决策数、时间、待恢复行动与完成状态 |

默认状态视图上限 28,000 字符，稳定指令＋动作 schema＋状态视图另设 70,000 字符检查。这些是 `AgentConfig` 中的工程默认值，不是精确 Token 计量或通用最佳值。

## 数字从哪里来

面板直接来自真实账本，`compare` 显式限定任务、seed、端点和评价次数。局部完整可以支持下一步判断，不能满足全合同完成门禁；`purpose=check` 排除，重复端点评价不成为新的训练种子。

默认排名只比较条件相同、完整的可比端点。模型还可以读取明确标注的局部观察并决定追加实验；不把不同候选各自最好的训练量混在一起排名。baseline 和所选方法的开发确认均完整才能冻结，九任务最终确认仍在研究者之外。

## 如何查回细节

`inspect` 读取候选文件、计划、schema 或反馈；`query_experiments` 查询实验、面板、缺失单元和来源索引；`read_trial_log` 分页读取堆栈与按步数筛选的指标；`read_source`／`find_source` 获取资料片段。

研究进度里的 `action_id` 可直接用 `inspect(target='feedback', id='action-编号')` 查回该行动的完整反馈，包括已退出最近上下文窗口的旧结果。重复读取保护会给出第一次成功读取的行动编号。

如果所有者在原部署目录内登记了控制层源码迁移，旧试验仍可通过 `query_experiments` 和 `inspect(trial)` 查看，但不进入新实现的面板和可续训列表。其检查点保持原训练身份；新训练从零开始并使用新的源码身份。

分页返回 `next` 或 `next_offset`。超长单行也保留字符偏移，不把截断伪装成完整读取。论文没读完、PDF 提取不足和提供方截断都不是“已完整理解”。

## 超限处理

先减少非关键记忆，再减少较旧候选卡片及其面板，将长反馈改成预览和读取引用，必要时把计划细节交给工具。最新读取的反馈只保留一次详细视图；研究进度保留关键里程碑和稳定行动引用。`context_control.reductions` 明示裁剪类别；数据库和工件不删除。

baseline、协议、预算和读取能力仍然可用。必要目标和协议本身装不下时报告 `configuration_error`，不是实验预算耗尽。默认只是有界信息装配，不是无限规模数据库或分布式调度。

## 记忆与边界

事实账本仍保存每项实验，默认视图不让大量自动 episode 笔记挤占空间。优先查询 hypothesis／procedure／literature／decision 类记忆，依据词语重合、时间与重要性取少量内容。没有向量数据库或跨项目全局自动记忆。证据 ID 可以核验存在性，解释是否成立仍需检查原始资料和实验。

`demo` 另有脚本控制器使用的紧凑状态，不会发送给真实模型。脚本路径的固定晋级安排不能被描述成真实模型已经合理分配了实验预算。

代码入口见[阅读指南](reading-guide.md)。上下文规模夹具、长反馈等原有回归保留；历史测量位于历史 evidence，不当成本次新的 D4RL 或模型效果结果。
