# v0.6.2 uv-local：安装范围、Review 与验收

本轮在 v0.6.1 Kimi 教材包上调整安装和执行环境，满足“不要 Docker、不用 sudo、
下载和缓存放在项目内”。不是算法升级，也不重写研究提示和实验协议。

## 已修改的路径

| 原问题 | 本版处理 | 验证 |
|---|---|---|
| 首次安装调用 apt/sudo | 删除系统安装路径，仅做编译器、OpenMP、GL/OSMesa 只读预检；Runner 拒绝系统安装和容器直接命令 | 禁止调用的负向测试；实际缺 GL/osmesa.h 时明确停止 |
| 默认依赖 Docker | 安装入口只有本地 Python/禁用源码两种模式，默认已授权本地；本地运行时拒绝旧 Docker 合同 | 默认学生/部署配置、执行路径及无 daemon 情况测试 |
| uv 在全局安装或命中另一环境 | 复制固定 uv 或提取固定 wheel 到项目，创建本项目 venv；每次安装显式 --python | 实际 uv 新 venv、构建与安装离线 Wheel，未开启系统包共享 |
| 缓存落到家目录或 /tmp | 单一目录表覆盖 HOME/XDG/uv/pip/模型库和临时路径，安装/主进程/worker 继承 | 故意配置外部 venv、缓存和安装变量的测试；父环境恢复 |
| --root 或软链接指向另一项目 | 安装 root 限于源码子树，管理路径拒绝已有软链接和父路径穿越 | 外部目录与参数化软链接反例 |
| 模型 Key 流入构建或候选程序 | 保留原 credential allowlist，补回的只是不含 Key 的本地目录变量 | Kimi 和新 worker 子进程测试 |
| 不用 Docker 后却仍声称沙箱 | 安装与研究预算确认均解释本地权限，文档明确 venv 不是文件/网络隔离 | 提示和授权回归；不宣称拦截任意 Python |
| 升级静默复用旧运行 | 实现/环境身份继续绑定，新安装目录，保留旧研究 | 原身份、恢复和预算测试保留 |

旧代码中通用容器类为兼容低层 API 仍可被导入，但**本包安装器和项目启动路径不调用它们**；
管理进程中的 ARLAB_LOCAL_ROOT 会令容器路径明确拒绝，不向它转交本地运行。
本版不携带原 worker Dockerfile，不需要安装或运行容器服务。

## uv 是真实安装器，不是换一个命令名称

使用 `uv python install --no-bin`、`uv venv --no-project` 与
`uv pip install --python <root>/venv/bin/python`。uv 自身取固定 0.10.0，默认 Python
固定为 3.10.19；已安装同版 uv 时复制并记录 SHA256，不修改原二进制。

由于本环境不能正常解析外部服务，实际新建 venv 的测试使用现有 Python 3.13，
并从本地 Wheel 安装。**这没有验证目标 Python 3.10／Torch 2.5.1／MuJoCo 的联网组合。**
安装命令及依赖顺序另有测试，不把命令被构造等同于依赖安装已成功。

## 保留的限制

uv 管理的是 Python 依赖，不会自动提供所有系统库。本机没有 GL/OSMesa 时停止是
本版明确设计，不用 sudo 补救。教师可以使用已经具备库的机器，或在程序已登记的
项目 native 前缀中准备兼容文件。没有加入一个不透明的系统库下载器。

“项目内写入”适用于本项目安装、包装器和正常遵循缓存设置的依赖；任意候选代码、
恶意构建脚本和硬编码绝对路径仍可越界。共享 CPU/GPU/磁盘负载也不会因 venv 而隔离。
缓存目录隔离会把 arXiv 限流锁限制到一个项目，跨项目并发仍需教师协调。

依赖采用主要版本固定与运行回执，不是所有传递依赖的跨平台哈希锁。第三方注册表
提供的哈希检查一致性，不等于独立身份认证。API Key 不落盘不等于 HTTP 传输已加密。

完整路径和使用边界见 [项目内安装合同](project-local-install.md)，旧运行处理见
[迁移说明](migration-uv-local.md)。研究本身仍由原 Harness 和独立证据门禁控制。
