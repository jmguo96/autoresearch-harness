# v0.6：低成本试探，由模型选择扩大实验

这是对 v0.5.1 的研究协议和代码修复，不是新的性能结果。保留固定 IQL、in-sample 价值学习、免额外搜索密钥的论文/公开代码调研、三分布开发池和九任务最终确认；不包含 RSI。

## 学生入口不变

在具备 C/C++ 编译器的 Linux x86_64 环境，解压到新的源码目录后运行 `bash start.sh`。实验室地址与 Kimi 选择已预置，学生只需填写模型 API Key；v0.6.3 使用项目内 uv，并可在项目内自动补齐匹配发行版的 GL/OSMesa 库，不使用 Docker 或 sudo。正式研究前显示并确认完整预算。旧版本研究不能原地接续，因为源码、训练日程和结果协议已改变。

## 模型现在决定哪些事

开发池固定为 `halfcheetah-medium-v2`、`hopper-medium-replay-v2`、`walker2d-medium-expert-v2`。

每个新方向可以先选其中一个任务、一个种子，训练约 5,000 步，评价 3 个 episodes。5,000 是起点建议，不是认定其足以预测百万步表现。模型可以用 `compare` 显式选取匹配子面板、读训练曲线和诊断后决定：

* 用同一检查点继续训练；
* 在开发池增加第二、第三个任务；
* 从允许的 0–9 中增加训练种子；
* 增加评价 episodes（最多 10）；
* 调研、修改代码、保留慢热方向或终止一个分支。

这不是固定晋级分数，也不要求每个候选先跑满三任务或三种子。Hopper 等环境和数据构造的影响在三任务子集中仍然混杂，不能凭局部结果作分布因果归因。原来的 3×3 开发完整性要求保留在 **freeze 门禁**：baseline 与所选候选都完成三任务、确认种子 0/1/2、1,000,000 步、10 个评价 episodes 后，才允许固定方法。额外种子不是强制要求，也不能重复计成新的独立种子。

最终仍是完整九任务、五个新训练种子、每次百万步、10 个评价 episodes。开发阶段不可运行其余六项。最终只评价一个冻结方法和 IQL，不把最终成绩送回模型调优。

## 真续训，而不是重启一遍

`run.steps` 和 `continue_trial.steps` 都是 **累计目标步数**。

```json
{"kind":"run","candidate":"c-...","case":"halfcheetah-medium-v2","train_seed":0,"steps":5000,"eval_episodes":3}
```

```json
{"kind":"continue_trial","trial":"t-...","steps":20000,"eval_episodes":3}
```

第二个动作保留已完成的 5,000 步，只预留并执行新增 15,000 步。`run` 也会自动复用同一方法、数据、种子和训练日程的最新兼容检查点。

训练日程在第一次运行之前固定为最终开发上限（默认百万步）：IQL 的学习率衰减、源码候选的 `BuildSpec.total_ticks` 不随暂停端点改变。恢复模块、优化器、调度器、控制器及随机数状态；每个端点保存独立工件，前一个端点不被覆盖。更改源码、配置、数据、种子或日程产生新轨迹，不能继承不兼容状态。

如果目标步数不变、只增加 `eval_episodes`，系统复用验证过的训练工件，重新评价，不重训。评价不是免费的，重复执行的 episodes 仍计费。分段间端点评价也消耗时间。

低预算独立重启试验与同一长期日程的训练前缀含义不同。本版默认选择后者，解决旧版“5万步衰减到零，再声称直接续成百万步”的歧义。独立单文件 `train` 没有显式 `schedule_steps` 时仍使用其请求训练总量，不可混用两种协议的成绩。

## 高预算不是目标支出

默认完整研究的上限：128 个活跃分支（含 baseline），10,000 份不可变方法版本，20,000 次正式实验，2,000 次实现检查，40,000 个执行尝试，20,000 次决策，40,000 次模型调用尝试，160,000,000 个输出 Token，1,000,000,000 训练 tick，16,000,000,000 优化器步，200,000 个评价 episodes，60 天运行窗口。

这些上限相互制约，不保证把所有方向全部跑满。它们是用户批准的最坏资源边界，不是调度计划、性能保证或应当消耗完的额度。模型可以在合理结论形成后结束；大型预算并不改变最终证据标准。检查和失败也计费。上下文提供剩余决策、时间和其他预算，避免模型临近截止仍盲目扩张。

## 工具与证据

* `continue_trial`：累计端点续训/增加 rollout 数。
* `read_trial_log`：读取已知开发 trial 的日志、堆栈、数值指标；可按行、训练步和字段选择。没有任意宿主文件读取权限。
* `compare`：可明确给 `cases`、`train_seeds` 和 `eval_episodes`，只比较条件一致的观察；局部完整不等于合同完整。
* `set_branch_status`：归档/重新激活方向，历史保留；源码修订不再占一个新方向。

代码修改后仍需检查 in-sample 的登记接口及数据依赖；运行钩子和容器不是任意 Python 的数学正确性证明。日志也是不可信数据，不是对模型的新系统指令。

## 最终复验恢复

最终 nominal panel 和恢复余量分开列出：默认 25% 额外重试槽，至少能容纳一个实验单元的两次重试，每个单元最多三次尝试。启动前按最大方法开销核对这一容量与用户硬上限；不足时零作业启动。基础设施错误有限重试；价值约束或数值非法不靠换种子掩盖。失败时已预留的不确定消耗不归零，重新启动也不增加预算。

恢复余量有限，不保证任意数量的故障都能完成。耗尽后报告不完整并停止，而非伪造低分或自动追加授权。

## 结论范围

报告分别给全九项描述性增益、开发任务复验和六个未用于搜索任务的证据。`method_improved` 仅作为兼容字段，对应未用于搜索任务的配对证据，不再由开发任务拉高总均值就置真；该字段也不表示普遍性能、因果机制、新颖性或智能体优越性。
