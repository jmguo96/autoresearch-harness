## 自适应探索不是降低最终标准

`run` 可在授权开发池中选择单任务、单 seed、1,000–1,000,000 范围内的累计端点。默认建议 5,000 步和 3 个 rollout episodes。`compare` 的 cases/seeds/episodes 子集明确标记，局部完整不能满足全研究完成门禁。模型自主决定增加训练、任务、seed 或 episodes；运行层不设一个自动“加分就晋级”的阈值。

源码修改不被限定到固定 IQL 骨架；正式最终池仍独立。模型不得提前用其余六任务选方法。`purpose=check` 不能贡献正式面板。完全相同的训练条件只计一个独立训练单元，不把更多端点/episodes 当成更多训练种子。

## 续训的具体语义

`checkpoints.py` 将训练轨迹身份与观察端点分开。日程上限在第一次训练前绑定，恢复完整状态；继续到新端点只预留新增 tick/optimizer 上界。新任务、新 seed、新源码/配置产生新轨迹。增加评价 episodes 时复用训练工件，不重训，但评价仍计费。

固定 IQL 与两种源码模板都在 CPU 上比较了 5→11→18 的分段训练和一次 18 步训练：网络、优化器、调度器及相关随机状态逐值一致。还通过 TrialService/worker/独立评分的完整路径执行续训，不只直接调用训练函数。

这不是百万步 D4RL 实验，也不保证未测试硬件上的确定性；进程启动、数据载入与检查点 I/O 仍有开销，不能把减少训练 tick 当成同等比例的总时间加速。

## 预算与恢复边界

高预算是用户可审阅的硬上限，不是期望消费量。模型仍应在有结论时结束，或者在结果不足时诚实停止。预留、已知实际用量、最终名义工作量和恢复容量分别记录；没有在恢复时清空额度。全局尝试池与单个实验尝试次数都有限，不能保证任意数量的故障都能完成。

默认大方向数不表示所有方向可以全部跑满；容量预览明确标注非调度计划。同 tick 不等于同 FLOPs 或相同推理成本。大量训练也会增加存储和 I/O，当前没有自动删除科研检查点以腾空间的策略。

## 测试过程透明说明

第一轮旧回归：3 个断言仍对应旧预算/单次失败策略，需更新到新协议；其余测试通过。新增测试发现脚本化教学上下文仍遍历全部修订，已改为活跃分支最新版本视图。一次整套运行还暴露了第二个旧“只发生一次重试”的幂等计数断言，同步修正后再次完整运行。日志全部保留，不把早期失败隐藏成首次全通过。

构建环境没有 `build` 模块，随后使用已有 pip/setuptools 的离线本地 wheel 构建。没有为此联网安装依赖。Wheel 在独立目录安装后执行了小规模真实合成训练及新协议生成。

## 不声称完成的验证

未运行真实模型自主研究、官方 D4RL 全量训练、MuJoCo 编译、CUDA、Docker 或在线文献服务。独立示例使用显式脚本决策器、合成环境和很少更新，虽然完整执行了研究到最终面板流程，也不是正式研究成绩。无 RSI；没有证明智能体优越性或算法性能提高。

IQL 数学更新方法通过 AST 对比保持不变；网络、数据、配方及 in-sample 边界模块与 v0.5.1 字节一致。训练包装层因续训而修改，不能宣称整份 trainer.py 未变。任意 Python 的 in-sample 正确性仍依赖登记接口、可见数据流和代码审阅，不是形式证明。
