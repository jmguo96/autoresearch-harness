# v0.6 架构：开放研究，稳定驾驭系统

本例的 Harness 位于模型和环境之间，组织**运行时循环、权限控制、状态持久化**。规划、记忆、工具使用与反馈在该运行结构中协同；它们不是四个常驻 Agent。本阅读整理版不修改这些运行机制。

## 1. 先分清两条执行路径

```text
学生入口 start.sh → classroom.session.run_study
                         │
                         ├─ 开发：Harness.run
                         │     上下文 → 决策 → 授权行动 → 真实结果 → 状态与反馈
                         │     行动可包括调研、读写候选、检查、训练、续训与比较
                         │
                         └─ 方法冻结后：audit_campaign(split="final")
                               固定 IQL 与一个冻结方法 → 九任务重训 → 程序汇总
```

开发过程由模型选择路径，最终确认是研究前已授权的程序流程。`finish` 只结束开发并冻结方法；学生入口自动衔接最终审计。独立审计仍不是模型工具，最终成绩不回流已冻结研究者。

底层 `arlab run` 只运行开发 Campaign，不自动执行九任务确认；它与 `start.sh` 的完整研究入口不能混称。

## 2. 模块职责

下列源码路径均相对 `src/arlab/`。

| 模块 | 职责 | 不应混同的内容 |
|---|---|---|
| `core/harness.py` | 调用模型、分派工具、保存反馈、控制停止与恢复 | 不在主循环计算 IQL 损失或环境分数 |
| `core/context.py`、`panels.py`、`reading.py` | 有限研究视图、确定性摘要、分页查回 | 不把全部历史重放，也不让模型重算账本数字 |
| `core/capabilities.py`、`schema.py` | 共享权限视图、严格行动协议 | 模型希望调用不等于获得授权 |
| `core/store.py`、`branches.py` | 事实与事件、预算、研究方向和不可变修订 | 研究笔记不覆盖实验事实 |
| `core/experiments.py`、`checkpoints.py`、`diagnostics.py` | 单次实验、兼容续训、资源结算和受控日志读取 | 实验端点不是新的独立训练种子 |
| `research/` | 论文和公开代码的发现、获取、定位与引用 | 参考代码不会自动被安装或执行 |
| `algorithms/` | 开放源码接口、状态恢复、运行检查与策略工件 | 不固定 Gaussian actor、双 Q 或每轮更新顺序 |
| `tasks/iql/` | IQL baseline、D4RL 数据、环境与领域协议 | 通用接口不证明已验证其它研究领域 |
| `audit.py`、`classroom/reporting.py` | 冻结后的独立面板、恢复、统计与结论范围 | 完整面板不保证性能提高或新颖性 |
| `classroom/`、`deployment/` | 用户入口、授权、安装和数据准备 | 安装权限不是研究者或候选算法的工具 |

当前是单机、单研究决策流，同步等待工具，使用 SQLite 和文件工件；不是异步实验集群。不需要外部编码 CLI、向量数据库或多套编排框架。没有 RSI；`AgentConfig` 由用户设置并与运行绑定，不是模型可自改的资产。

## 3. 状态、身份与真正续训

研究方向（branch）保存假设的组织关系；候选修订（candidate）固定某份源码和配置。训练轨迹（series）进一步绑定算法、数据、seed、训练日程及请求中的执行条件；实验端点（trial）对应一个累计更新位置和评价条件。详细定义见[术语表](glossary.md)。

自适应开发从第一次运行前就固定 `schedule_steps`，默认百万步。5,000→20,000 复用兼容检查点，只增加 15,000 步；网络、优化器、调度器和随机状态一并恢复。更改方法、数据、seed 或日程产生新轨迹。仅增加评价 episodes 复用已验证训练工件，但评价仍计费。

同请求失败恢复与主动续训是不同路径。失败后已预留的不确定消耗不自动清零。源码按原始文件字节参与实现身份；本包的注释和排版也会改变哈希，不能据“逻辑一致”绕过原有恢复校验。

## 4. 信息与反馈

事实账本、当前上下文和研究笔记分开。`ContextBuilder` 选择当前候选、面板摘要、终止预算和少量笔记；正文、完整源码、堆栈与曲线经工具查回。完整反馈先保存为工件，再以有限视图进入下一轮。

实验结果、论文作者的结论和模型解释是三类来源。source/span 能证明某段材料被保存或读取，不能自动证明解释正确。计划里的 `done` 仍是模型工作状态；是否满足研究完成条件由实验面板检查。

## 5. 权限与安全边界

工具目录、可用动作 schema 和执行授权共享 `capabilities.py` 的能力视图。调研访问、通用网页搜索和源码执行分别授权；默认学生入口保留免额外搜索密钥的论文/公开代码工具，关闭通用网页搜索。

网络仅访问获准公共 HTTPS 主机，检查地址、证书、重定向、大小和预算。网页、仓库注释与日志是不可信资料，不是系统指令；没有通用提示注入免疫保证。有限 PDF 文本解析不含 OCR、视觉读图或图表数值核验。

`trusted_local` 是本地子进程，不是文件系统沙箱。本版安装入口不支持 Docker。训练候选与评分控制仍分进程，候选通过动作接口参与环境，不通过自报分数得分；但同一用户的任意 Python 能绕开进程/文件约定，因此不能宣称具有原容器的文件与网络隔离。uv 的目录/依赖管理见 [项目本地安装](project-local-install.md)。

in-sample 检查依赖完整登记的 Q/V、数据配对、价值参数与 buffer 冻结、优化器归属及有限张量来源追踪。隐藏网络、绕过接口或经 Python/NumPy 清除标记仍需代码审阅；运行检查不是任意 Python 的形式证明。

## 6. 资源、结束和证据范围

短程、单任务、单 seed 结果可以支持下一步选择；局部完整不等于开发确认完整。IQL 与所选候选满足[固定开发面板](nine-task-study.md)后才可冻结；保留负结果合法。最终协议预留有限失败恢复池，不能无限重试或自动追加预算。

全九项描述性结果、三个开发任务复验、六个未用于搜索任务分别报告。相同 tick 不等于相同 FLOPs 或策略推理成本；统计证据、算法正确性、方法新颖性与 Agent 能力要分别讨论。

当前依赖不是完整跨平台带哈希锁定，资料缓存不是分布式知识系统，arXiv 的同机同用户锁不覆盖多机。大量检查点没有自动删除策略。实际验证范围见[本次记录](../evidence/validation.json)，不把历史日志或合成实验称为真实 D4RL 结果。


## v0.6.1 的模型连接边界

学生入口预置实验室 New API，填写 Key 后查询可见 Kimi 并固定 ID。`core/endpoints.py` 只允许指定实验室 HTTP 地址的显式例外；它不影响上述资料访问的 HTTPS 边界。明文链路不提供 TLS 保护，详见 [Kimi API 说明](kimi-api.md)。研究主循环、算法检查、预算与审计不变。
