# v0.5 使用入口和九任务研究 Review

这是同轮源码自审与测试，不是第三方审计。执行范围和最终测试数量以 evidence/validation.json 为准。

## 已实现和检查

| 风险 | 处理 |
|---|---|
| “简化教学”误变成低训练量/单任务最终成绩 | 移除课堂小研究预算与 --full 分支；默认完整九任务协议；合成 demo 独立且显式标注 |
| 无搜索 Key 却持续调用 search_web | 工具目录、动态动作 schema 和执行授权使用同一能力视图；默认关闭 search_web；论文/公开仓库保持免额外 Key |
| 完成开发就宣告研究完成 | Campaign 只冻结开发选择；学生入口自动调用最终确认；report 的 research_complete 根据全部任务/种子的证据计算 |
| 最终只运行剩余八项，少了开发任务 | final_evaluation 明确枚举九项；开发任务用新种子重训，并披露它不是未见任务 |
| 挑测试赢家或最终分数回流 | 只评价一个冻结方法与固定 IQL；最终数据单独账本，研究者没有 audit 工具 |
| 复验参数可临时替换 | 最终协议研究前绑定；final 调用禁止覆盖 seeds、horizon 和额度；输出路径也绑定 |
| 不同算法更新次数上界未计入预算 | 启动前按冻结算法上界估算；额度不足时零作业启动；没有自动扩权 |
| 失败或恢复伪造完整分数 | 逐项原子进度；异常不填零分；缺任意任务/seed 不发布完整 audit；复用已完成执行 |
| 学生明文存密钥、误执行命令 | getpass 或环境变量；只保存模型地址/名称；拒绝内嵌密钥/远程 HTTP；不使用 shell=True 拼接输入 |
| 保留 baseline 却重复跑两遍 | 相同冻结方法按内容身份去重，45 项而不是重复90项 |
| 修改测试时取消重要安全机制 | 数据/算法/评价授权保持；新增测试验证关闭工具不能进入服务；修改旧解析测试仅为显式授权后再检查解析错误 |

## 第一轮测试发现

初次回归中两个旧测试未授予调研权限，新的授权边界优先拒绝了它们；已补充测试前置授权，不放宽执行层。审计预算错误信息保留了旧回归所需的明确“启动前拒绝”语义。

有一项最初测试期间由于并发编辑源码触发 worker/评分器实现哈希不一致，属于预期的完整性阻断。随后停止修改源码，在固定版本上重新运行完整回归，最终日志另存。这些早期失败没有隐瞒为一次全部通过。

## 仍需实际验收

实际 D4RL/MuJoCo 编译、官方完整数据下载、GPU/Docker 和真实模型服务未在本环境完成验收。以合成环境执行的九任务协议测试不能替代正式 90 个训练作业。

arXiv/Crossref/GitHub 不要求额外搜索 Key，不等于无网络条件或无限额度。通用网页搜索仅关闭，没有偷偷改用不稳定匿名服务。

任意 Python 候选的 in-sample 检查仍依赖诚实登记和可见数据流，Docker 也不证明算法正确。单个研究轨迹、完整九任务表都不自动证明 Agent 能普遍发现更好方法。

默认完整研究可能需要大量计算；界面简单不表示计算便宜。预算耗尽后保持不完整状态，不能通过新目录重复使用测试结果而声称独立验证。
