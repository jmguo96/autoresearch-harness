# Autoresearch Agent 0.5.1：三种分布探索，九任务确认

**默认：3 个 D4RL 任务覆盖 3 个环境与 3 种数据分布 → 冻结方法 → 全部 9 个任务复验。**

这个版本简化的是安装与使用，不是研究规模。固定 IQL 是唯一对照；候选可以修改完整算法源码，价值学习保持 in-sample；规划、调研、工具、记忆、反馈均保留。没有 RSI。

## 学生只需这个入口

```bash
bash start.sh
```

首次运行会准备环境和九份数据，询问模型服务地址、模型名称、隐藏输入的模型 API Key，并显示完整研究预算供确认。已有部署会复用，不需要手工激活虚拟环境、复制配置文件或下载数据。

**环境前提：Linux x86_64（Ubuntu/Debian/相应 WSL2）、Bash、宿主 Python 3.10+。完整源码研究默认使用已安装且当前用户可访问的 Docker；GPU 是可选项，需要预先具备驱动。** 入口不会自动安装驱动、修改用户组或降级到不受保护的本地执行。教师可在课程账号/镜像中先执行 `bash start.sh setup`。首次联网部署仍取决于包服务、D4RL 数据和 legacy MuJoCo 环境能否正常取得和编译。

论文检索使用 arXiv/Crossref，公开代码检索使用 GitHub，**不要求额外搜索 API Key**；它们仍有网络和限流条件。通用网页搜索默认从工具菜单、模型动作 schema 和执行入口关闭，不再要求 Brave 账号。调研失败会留下失败反馈，不会编造搜索结果。

查看结果和继续运行：

```bash
bash start.sh report
bash start.sh                 # 同名研究继续，不覆盖已有实验
```

模型地址、名称只需配置一次；密钥只在当前进程使用，不写入 `model.json`。下次可以继续隐藏输入，或由教师预先设置 `ARLAB_API_KEY`。

## 完整研究要求，不是少量训练演示

| 部分 | 默认协议 |
|---|---|
| 三任务探索 | `halfcheetah-medium-v2`、`hopper-medium-replay-v2`、`walker2d-medium-expert-v2`；每项 3 个训练种子；50,000 / 250,000 / 1,000,000 三档更新 |
| 冻结 | 选择一个方法的源码和配置，保留原始 IQL 对照；选择原 IQL或负结果也合法 |
| 最终确认 | 3 个环境 × 3 种数据分布，共 9 项；每项 5 个新训练种子，每次 1,000,000 次更新、10 个评价 episodes |
| 报告 | 逐任务 mean/std、配对差值、不确定性、证据覆盖；全九项、开发三项复验、未用于本次搜索的六项分别报告 |

九项全部是 `-v2`：

| 环境 | medium | medium-replay | medium-expert |
|---|---|---|---|
| HalfCheetah | 探索＋最终 | 最终 | 最终 |
| Hopper | 最终 | 探索＋最终 | 最终 |
| Walker2d | 最终 | 最终 | 探索＋最终 |

三个探索任务在实验前固定，不按结果选择；这种对角组合提供初步覆盖，但不能分离环境和数据分布的影响。跨组合表现仍由完整九任务面板检查，不把这三项宣称为最优或充分代表所有任务。

实现调试可在一个开发任务上做低成本 `check_candidate`；这些检查不参与排名。**正式比较和冻结要求 IQL 与候选各自完成同一档位的 3 任务 × 3 种子共 9 个单元**，只跑一个任务或全部选择 medium 都不满足当前教材协议。

**IQL + 一个不同的冻结候选，共 9 × 5 × 2 = 90 个完整训练作业，尚不含探索成本。** 选择 IQL 本身时只运行一组 45 个，避免重复计算。

这不是把某个开发任务上训练出的权重放到所有任务里运行。固定的是**方法源码与配置**，每个任务都要用其自己的离线数据重新训练。最终任务不能由研究者 `run` 工具提前访问；独立评价是入口的 owner 操作，不调用模型选择“测试集赢家”。

最终面板缺一个任务/种子、执行失败或预算不足时，只输出 `final_evaluation_pending` 和不完整进度；不会把开发任务成功当成完整九任务结论。完整面板也不保证有提升，负结果和不确定结果仍应如实呈现。

三个开发任务即使用新种子也不是未见任务，报告与其余六项分开说明；看完最终结果继续改方法，会消耗这组测试的独立性，换名称或种子不能恢复。

## 输出放在哪里

```text
.arlab/d4rl9/
├── model.json                  模型地址和名称，不含密钥
├── configs/research.json        自动生成的完整研究协议
├── data/                       原始数据、转换数据与哈希
└── runs/study/
    ├── development/            调研资料、候选、开发实验、冻结方法
    ├── final/                  最终评价账本、逐任务工件、实时进度
    ├── report.md               先阅读这里
    ├── report.json             结构化结果与证据状态
    └── results.csv             九任务结果表
```

中断后重新执行相同命令。已经完成的实验和审计结果复用；未完成尝试继续消耗获准预算，不会通过恢复自动重置预算。报告生成不需要模型调用。

## 教师与开发者入口

```bash
bash start.sh --dry-run         # 只预览，没有下载、sudo、写文件或模型请求
bash start.sh --advanced-help   # 教师/自动化选项
```

完整说明见 [快速开始](quickstart.md)、[九任务研究协议](nine-task-study.md)、[底层部署](deployment.md)。从旧版升级请按 [迁移说明](migration-0.5.1.md) 使用新目录，不覆盖单任务旧合同。底层 `deploy.sh` / `arlab` 命令仍保留；学生无需学习全部参数。

无 MuJoCo、无模型密钥时，可显式执行 `bash start.sh demo` 检查合成环境流程。**这不是默认研究路径，也不能用于九任务结论。** 不会在真实研究失败时静默使用演示或测试资料。

## 源码阅读路径

`classroom/bootstrap.py → classroom/session.py → core/harness.py → core/context.py → core/experiments.py → audit.py`。

先看输入如何转为计划/工具调用，再看实际结果如何进入下一轮上下文。资料与完整实验记录保存在外部，当前上下文只取需要的部分。独立九任务确认是研究方法冻结后的受保护操作，不是 RSI。

算法主体仍在 `tasks/iql/` 和 `algorithms/`，没有重新限制 Gaussian actor、双 Q、损失形式或更新顺序。运行时检查依赖正确的模块登记与可观测数据流，**不是任意 Python 的形式验证**；`trusted_local` 也不是沙箱。

本次协议与迁移 Review 见 [review-v0.5.1.md](review-v0.5.1.md)。

## 验证边界

本版本测试数量与实际运行环境见 `evidence/validation.json`。已用真实小规模 CPU IQL 和合成环境验证“探索 → 冻结 → 九个任务的独立评价 → 报告”的连接，但这不是 D4RL 性能复现。

当前交付环境没有完成干净机器上的联网 D4RL/MuJoCo 安装、真实模型服务、CUDA 和 Docker 验收。单元测试中的九任务身份、模拟 HTTP 返回或训练替身不能算实际 D4RL、搜索服务或模型成绩。
